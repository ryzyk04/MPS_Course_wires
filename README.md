# Провода — Arduino Uno

Прошивка реализует правила всех трёх сложностей из «Руководства по обезвреживанию».

## Подключение

| Элемент | Подключение |
|---|---|
| Восемь адресных WS2812B | D8 → резистор 330 Ом → DIN первого; DOUT → DIN следующего |
| Питание WS2812B | 5V и общий GND с Arduino |
| Игровой провод П1 | D3 → разрываемый провод → GND |
| Игровой провод П2 | D4 → разрываемый провод → GND |
| Игровой провод П3 | D5 → разрываемый провод → GND |
| Игровой провод П4 | D6 → разрываемый провод → GND |
| Игровой провод П5 | D7 → разрываемый провод → GND |
| Кнопка сигнала | D9 → кнопка → GND (`INPUT_PULLUP`) |
| UART к ESP32, RX | D10 ← ESP32 GPIO2 (TX) |
| UART к ESP32, TX | D11 → делитель уровня 5 В → ESP32 GPIO4 (RX) |
| Светодиоды ленты 1–5 | Цвета пяти проводов |
| Светодиод ленты 6 | Выключен |
| Светодиод ленты 7 | Статус решения |
| Светодиод ленты 8 | Сложность: зелёный — лёгкий, жёлтый — средний, красный — сложный |

Светодиоды и физические провода нумеруются слева направо. Нужна цепочка минимум из восьми адресных светодиодов. Восьмой имеет индекс 7 в коде. Отдельный RGB больше не используется. D8 управляет лентой, D9 — кнопка, D10/D11 — UART. D0/D1 остаются для USB Serial и загрузки прошивки.

Входы проводов настроены как `INPUT_PULLUP`: целый провод замыкает вход на GND (`LOW`), разрыв позволяет внутренней подтяжке установить `HIGH`. Внешние подтягивающие резисторы не требуются. Игровые провода не подключать к 5V и не включать в цепь питания светодиодов. Для макетного теста можно размыкать перемычки вместо перерезания.

## Настройки и запуск

В начале `src/main.cpp`:

- `STRIP_BRIGHTNESS = 40` — яркость светодиодов проводов 1–5: от 0 (выключены) до 255 (максимум). После изменения загрузить прошивку заново.
- `STATUS_BRIGHTNESS = 30` — яркость индикаторов статуса и сложности (светодиоды 7 и 8), от 0 до 255. Яркость каждого пикселя задаётся отдельно.
- `DEBUG_SOLUTION = false` — при `true` монитор порта показывает физические позиции нужных проводов.

При включении Uno ждёт WAITING_FOR_COMMAND, лента выключена. В вебе выберите сложность и нажмите «Отправить»: сид генерируется на сервере, параметры сохраняются на ESP32. Затем нажмите D21 на ESP32 для передачи игры Uno. Uno получает готовые сид и уровень, вызывает randomSeed(seed + 1) и по этой последовательности строит раскладку. Смещение на 1 позволяет использовать и сид 0000: Arduino AVR игнорирует randomSeed(0). Одинаковый сид и уровень дают ту же раскладку, независимо от ранее сыгранных игр. Новая команда сбрасывает прошлый результат и ждёт замыкания всех пяти проводов в течение 150 мс. D9 и UART работают и до получения задачи.

## Кнопка и двусторонний UART

На обеих платах UART работает на **9600 бод, 8N1**. Uno использует `SoftwareSerial` (RX D10, TX D11), ESP32 — аппаратный UART2 (RX GPIO4, TX GPIO2). Соедините GND плат.

При прошивке ESP32 отсоединяйте линию ESP32 D2 → Uno D10: GPIO2 влияет на вход в загрузчик. После загрузки возвращайте соединение при выключенном питании. На Uno прошивка и пины UART не меняются.

**D11 Uno нельзя подключать прямо к GPIO4 ESP32: у Uno уровень TX 5 В.** Используйте преобразователь уровня либо делитель: D11 → 1 кОм → узел GPIO4 → 2 кОм → GND. Обратная линия GPIO2 ESP32 → D10 Uno передаёт уровень 3,3 В. Не подключайте линию UART к питанию.

Каждое нажатие D9 после антидребезга 40 мс отправляет `W:BUTTON:<id>\n`. После отпускания на 10 мс кнопка готова к следующему нажатию, в том числе после победы или ошибки. Удержание не создаёт повторных событий; кнопка, зажатая при включении, должна быть отпущена и нажата заново. ESP32 выдаёт **300 Гц на 200 мс**, прерывая текущий звук, и отвечает `E:ACK:<id>\n`. При потере подтверждения Uno повторяет последнее неподтверждённое событие каждые 500 мс; ESP32 подтверждает повтор без нового звука. При новом нажатии оно заменяет предыдущее неподтверждённое событие. Это передача последнего события, не долговременная очередь всех нажатий. ID и подтверждения не сохраняются при отключении питания.

Для обратного направления ESP32 каждые 5 секунд отправляет `E:PING\n`, Uno отвечает `W:PONG\n`. Ответ виден в USB-мониторе ESP32. Дополнительные команды ESP32 → Uno добавляются в `handleEspLine()`; отправка с ESP32 — через `sendWiresLine()`. Построчный протокол и разбор ID находятся в `shared/uart_protocol.h`. Частичные строки собираются, строки длиннее 47 символов отбрасываются до конца строки. Контрольной суммы нет. При повреждении события оно повторяется после таймаута. Короткая передача `SoftwareSerial` и обновление WS2812 используют прерывания, поэтому проверка на реальном подключении обязательна.

Запрос задачи: E:GENERATE:<round_id>:<seed>:<level>, ответ W:GENERATED:<round_id>, каждая строка заканчивается переводом строки. Сид — 0–9999, уровень — 0/1/2. ID раунда создаётся ESP32 по нажатию D21 и отличается от ID команды веб-сервера. Uno запоминает последний ID в RAM: его повтор только подтверждается, новый ID генерирует задачу с полученными параметрами. ESP32 повторяет запрос каждые 500 мс до подтверждения. Повторное нажатие D21 позволяет заново начать ту же раскладку. Если нужно изменить сид или уровень, сначала отправьте новые данные из веба. Старый формат без сида и уровня не принимается.

Перед стартом подключить **все пять** проводов. После непрерывного замыкания на 150 мс в мониторе порта (115200 бод) появляется `READY`. До этого разрывы не считаются ходами. Седьмой светодиод мигает жёлтым и при ожидании подключения, и во время решения.

Разрыв учитывается после стабильного `HIGH` в течение 40 мс. Нужные позиции вычисляются один раз по исходной раскладке: после разрыва провода нумерация и ответ не меняются. Если нужны два провода, разорвать их можно в любом порядке; после первого правильного разрыва седьмой светодиод продолжает мигать жёлтым. Разрыв неактивного провода игнорируется.

Все нужные провода разорваны → седьмой светодиод постоянно зелёный. Разорван лишний активный провод → седьмой постоянно красный. Повторное замыкание не отменяет результат. Для новой игры при необходимости отправьте новые параметры из веба, затем нажмите D21 на ESP32 и восстановите все пять проводов. Новая команда работает из любого состояния, сбрасывает результат и ждёт замыкания всех проводов в течение 150 мс. Reset выключает ленту и возвращает ожидание команды.

При победе Uno отправляет W:SOLVED:<round_id>, при ошибке — W:FAILED:<round_id>. ESP32 играет базовую мелодию «Победа» или «Поражение» из веб-пульта, а при поражении дополнительно снимает 30 секунд с таймера. Ниже нуля время не опускается; при обнулении работающего таймера вместо мелодии звучит сигнал окончания. Подтверждение — E:RESULTACK:<round_id>. Uno повторяет результат каждые 500 мс до подтверждения. Повтор результата или результат старого раунда не приводит к повторному штрафу и звуку. Новая задача отменяет повтор старого результата. Состояние обмена хранится в RAM.

Сборка: `pio run -d wires` из корня репозитория. Для загрузки: `pio run -d wires -t upload`.

Проверка логики на компьютере: `python wires/test/check_logic.py` (нужен `g++` в PATH). Проверяются допустимость ответа для всех цветовых раскладок на наборе сидов, отдельные примеры приоритета правил, антидребезг и состояния игры. Эти проверки не заменяют проверку подключения на плате.
