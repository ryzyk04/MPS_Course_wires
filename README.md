# Провода на ATmega328P

Нативная прошивка AVR для платы Uno, 16 МГц. Проект собирается PlatformIO.
Роль временного шлюза сохранена.

```text
ESP32 -- UART 9600 -- wires -- I²C 100 кГц -- simon     0x11
                                         -- labyrinth 0x12
```

Обмен использует общую библиотеку PuzzleBus и пакеты по 22 байта.
PuzzleMaster отвечает за команды, опрос и события, нативный TWI master
реализует аппаратный транспорт. Собственная игра использует PuzzleNode.

## Структура

| Каталог | Назначение |
|---|---|
| include/Config.h | Яркость, антидребезг, задержки, опрос и таймауты |
| src/game | Генерация по сиду, правила, состояния игры и индикация |
| src/communication | Построчный UART, подтверждения, повторы, шлюз двух модулей |
| src/drivers | GPIO, Timer0, Timer1 UART, аппаратный USART, TWI master и WS2812 |
| src/main.cpp | Инициализация и последовательность обработки основного цикла |
| test | Проверки правил, игры, обмена и моделей регистров |

Игровые классы получают снимки входов и время аргументами.
Обращения к регистрам AVR находятся в drivers.
Динамического выделения памяти в прошивке нет.

## Подключение

| Элемент | Пин Uno / порт AVR |
|---|---|
| Пять разрываемых проводов | D3–D7 / PD3–PD7, вторые концы на GND |
| Восемь WS2812B | D8 / PB0 через 330 Ом на DIN |
| Кнопка сигнала | D9 / PB1 на GND |
| UART от ESP32 GPIO2 TX | D10 / PB2 RX |
| UART к ESP32 GPIO4 RX | D11 / PB3 TX через делитель 5 → 3,3 В |
| USB debug | D0/D1, USART0 TX 115200 |
| I²C SDA | A4 / PC4 |
| I²C SCL | A5 / PC5 |

Все игровые входы имеют внутренние подтяжки. Замкнутый провод даёт LOW, разрыв — HIGH.
SDA/SCL общие для трёх Uno с внешними подтяжками 4,7 кОм к 5 В.
Платы имеют общий GND. ESP32 связан с этой системой по UART.
Для Uno TX → ESP32 RX сохраняется делитель 1 кОм сверху и 2 кОм к GND.
Подключение и протокол стенда описаны в [docs/bus.md](docs/bus.md).

Пиксели 1–5 показывают цвета физических проводов. Пиксель 6 выключен.
Пиксель 7 показывает состояние, пиксель 8 — сложность.

## Работа

При включении плата ждёт команду, лента выключена.
ESP32 отправляет E:GENERATE с номером раунда, сидом 0–9999 и сложностью 0/1/2.
Получив новый номер, wires создаёт задание и передаёт параметры двум I²C-модулям.
Повтор того же номера подтверждается без сброса прогресса.
Генерация использует ту же последовательность Park–Miller с seed + 1,
что прежняя прошивка Arduino AVR.

Перед игрой все пять проводов должны быть замкнуты непрерывно 150 мс.
Разрыв учитывается после 40 мс стабильного состояния.
Нужные провода допускается разрывать в любом порядке.
Ошибка имеет приоритет при одновременных разрывах.
Если лишний разрыв ещё проходит антидребезг, победа ожидает его обработки.

Жёлтое мигание означает ожидание проводов или решение.
Постоянный зелёный — победа, красный — неудачное завершение.
Результат сохраняется до следующей команды.
Сид и сложность готовятся прежним веб-пультом, D21 ESP32 начинает новый раунд.

Нажатие D9 после 40 мс отправляет W:BUTTON.
Отпускание 10 мс разрешает следующее нажатие.
Удержание не создаёт новых событий. Кнопка работает во всех состояниях игры.
ID кнопки резервируются блоками по 256 в двух записях EEPROM.
Маркер завершения и инверсия данных защищают резервирование при прерывании записи.
После перезапуска возможны пропуски ID. При полном обороте 32-битного диапазона
нумерация начинается заново.

W:BUTTON и W:SOLVED/W:FAILED повторяются раз в 500 мс до подтверждения ESP32.
Новое нажатие заменяет прежнее неподтверждённое событие кнопки.
Новое задание отменяет повтор прежнего результата.
Ведущая плата выполняет звуковое сопровождение и начисление штрафов.

Шлюз по очереди опрашивает один адрес каждые 25 мс.
Он проверяет размер, тип и CRC, передаёт текущий раунд подключившейся ведомой.
Малые ошибки передаются накопительным счётчиком.
ERROR и SOLVED повторяются до E:GACK.
Три неудачных опроса переводят ранее доступную ведомую в Offline.

## Драйверы и время

Timer0 работает в CTC с периодом 1 мс.
Timer1 с делителем 8 и PCINT0 обслуживают UART 9600 8N1 на D10/D11.
Каналы сравнения Timer1 отдельно обслуживают TX и RX, в том числе одновременно.
Аппаратный USART0 обслуживает USB debug.
TWI master ограничивает всю транзакцию таймаутом 2500 мкс и восстанавливает контроллер при сбое.

WS2812 передаётся с точными задержками для 16 МГц.
RX проверяется на границе каждого байта ленты, примерно через 10 мкс.
Входящий старт прерывает кадр ленты, после затишья передача повторяется полностью.
Обновление также ожидает завершения UART TX и интервала фиксации ленты.
При таком прерывании возможен кратковременный частичный рисунок до повторной передачи.
Драйвер требует проверки на реальном сочетании плат и ленты.

## Настройки

Значения находятся в include/Config.h.
Основные параметры — WIRE_DEBOUNCE_MS, BUTTON_PRESS_MS, BUTTON_RELEASE_MS,
READY_MS, BLINK_MS, STRIP_BRIGHTNESS, STATUS_BRIGHTNESS, BUS_POLL_MS,
UART_RETRY_MS и TWI_TIMEOUT_US.

Распиновка и тайминги WS2812 рассчитаны на ATmega328P 16 МГц.
При смене скорости UART её нужно согласованно менять на ESP32.
DEBUG_SOLUTION включает вывод нужных физических позиций в USB debug.

## Сборка и проверка

```powershell
pio run
python test/run_tests.py
```

Для загрузки используется pio run -t upload.
COM7 и скорость USB debug сохранены в platformio.ini.
framework и внешние библиотеки для сборки этой прошивки не требуются.

Прежние команды тестирования также доступны.

```powershell
python test/check_logic.py
python test/check_bus.py
python test/run_tests.py --group hardware
```

Для тестов нужен Python и g++.
Проверяются 30000 комбинаций сида и сложности и 2082024 цветовые раскладки
с контрольными значениями, снятыми с исходных правил.
Отдельно проверяются антидребезг, состояния, UART ACK/повторы, шлюз,
все 256 значений UART-байта, ошибки кадра и переполнение буферов,
потеря питания при резервировании ID и таймауты TWI.

Тесты исполняют настоящие игровые классы и драйверы UART/Clock/Board/TWI
с моделями регистров. Ассемблер WS2812 проверяется сборкой AVR и разбором машинного кода.
Реальные электрические уровни, точность выборки UART и сигналы ленты требуют стендовой проверки.

## Общая библиотека

Рядом с папкой проекта должна находиться папка puzzle_bus с library.json.
PlatformIO использует локальную зависимость symlink://../puzzle_bus.
В Simon и labyrinth собственные кодеки и ISR TWI удалены, используются
PuzzleNode и AvrTwiNode. В wires используется PuzzleMaster, в master —
общие UART-заголовки. Подробности приведены в [docs/bus.md](docs/bus.md).
Все участники I²C должны быть собраны с новой библиотекой одновременно.
